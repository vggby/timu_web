规划设计知识点结构化要点清单

知识点一：层次化网络设计原则

核心定义/结论

三层结构：核心层（高速转发）→ 汇聚层（策略/汇总/转换）→ 接入层（用户入口/认证/信息收集）。设计顺序从接入层开始，逐级向上。

典型题型与解题要领

  • 判断"哪项描述错误"
  • 抓两个高频陷阱：①设计顺序（从接入层开始，不是核心层）；②功能归属（过滤/策略路由是汇聚层的活，不是核心层）
  • 模块化要求针对核心层+汇聚层，接入层不强制

易错点与注意事项

  • 核心层只管高速转发，不做复杂控制，这是最常考的错误说法
  • "先设计核心层"是经典错误选项，记住"盖楼从地基开始"
  • 备用路径≠负载分担：备用路径平时不工作，同时工作的叫负载分担

知识点二：网络需求分析与逻辑/物理设计

核心定义/结论

  • 需求分析阶段 = 规划"要什么+花多少钱"，包含：总体需求、综合布线、可用性可靠性、安全性、工程造价估算
  • 逻辑设计 = 纸上规划（拓扑图、IP方案、初步软硬件需求）
  • 物理设计 = 落地实施（设备清单、布线、安装日程、测试、用户培训计划）

典型题型与解题要领

  • 判断某内容属于哪个阶段
  • 口诀：需求阶段管"要什么+花多少"；逻辑设计管"纸上画图"；物理设计管"真人真事"
  • 培训计划归物理设计，IP分配归逻辑设计，选型归实施阶段

易错点与注意事项

  • 工程进度安排、硬件选型、IP分配都不属于需求分析阶段
  • 用户培训计划是物理设计的输出，不是逻辑设计

知识点三：QoS与IntServ集成服务

核心定义/结论

IntServ 三种服务（仅三种）：

  • 保证服务：定量保证带宽/时延/抖动/丢包率
  • 负载受控服务：定性保证，类似网络欠载时的质量
  • 尽力而为服务：不保证任何质量，普通互联网

典型题型与解题要领

  • 判断哪种服务"不属于"IntServ
  • 只需记住三个名字，看到"突发式服务"直接排除

易错点与注意事项

  • "突发式服务"是高频干扰项，IntServ 里根本不存在这个分类

知识点四：网络冗余设计与负载分担

核心定义/结论

  • 冗余设计：备用路径平时不工作，主路径故障才启用，目的是防单点故障
  • 负载分担：多条并行链路同时工作，共同承担流量，目的是提升性能
  • 两者可以结合：有冗余链路时可配置负载分担策略

典型题型与解题要领

  • 判断哪项描述"错误"
  • 核心辨别：备用路径"同时工作分担流量"这个说法是错的，那叫负载分担不叫冗余

易错点与注意事项

  • 业务连续性（出故障能恢复）≠ 业务可用性（平时不出故障），两个概念经常混考

知识点五：SDN架构与网络设备OSI层次

核心定义/结论

  • SDN 三层：应用层 → 控制层 → 转发层（没有"逻辑层"）
  • OSI设备对应：集线器→物理层，二层交换机→数据链路层（MAC地址），路由器/三层交换机→网络层（IP地址）

典型题型与解题要领

  • SDN题：找"不包含"的层，答案通常是"逻辑层"（三层架构的词，混入SDN干扰）
  • 设备层次题：叫"几层交换机"就在第几层，规律直接用

易错点与注意事项

  • "逻辑层"属于传统三层架构（表现层/逻辑层/数据层），不属于SDN
  • 路由器比交换机延迟大（存储转发 vs 直接转发）

知识点六：网络拓扑与局域网特征

核心定义/结论

  • 星型拓扑：所有设备连中心节点，任意两设备通信最多2跳（设备→中心→设备）
  • 局域网特征：范围小、性能稳定、结构简单、拓扑多样、封闭性网（不是非封闭）

典型题型与解题要领

  • 星型拓扑跳数：直接记2跳，不可能更多
  • 局域网找错误项：抓"非封闭性"这个说法，局域网有边界有围墙，天生封闭

易错点与注意事项

  • "非封闭性网"是局域网题的经典错误选项，"域"字本身就意味着有边界

推荐复习顺序

  1. OSI模型与网络设备层次（基础，其他知识点的地基）
  2. 三层网络架构（核心/汇聚/接入的功能划分）
  3. 层次化设计原则（设计顺序、模块化要求）
  4. 网络需求分析 → 逻辑设计 → 物理设计的阶段划分
  5. 冗余设计与负载分担（概念区分）
  6. IntServ三种服务（纯记忆，5分钟搞定）
  7. SDN架构（纯记忆，认识三层名字即可）
  8. 拓扑结构与局域网特征（送分题，最后扫一遍）

网络协议 · 结构化知识点清单

一、DNS 域名解析

知识点名称：DNS 查询方式（递归 vs 迭代）

核心定义/结论：

  • 递归查询：被问方代替发起方继续查询，直到返回最终结果，服务器负担重
  • 迭代查询：被问方只返回"下一步去问谁"，发起方自己继续查，服务器负担轻
  • 根域名服务器只应使用迭代查询，若用递归会因负担过重影响性能

典型题型与解题要领：

  • 题型：判断DNS查询流程中哪个环节"不合理"
  • 要领：看"谁在用递归"，根域名服务器用递归就是错的；中介DNS用递归是正常的（帮客户端跑腿）

易错点：

  • 混淆"中介DNS递归加重根服务器负担"——实际上中介DNS递归是自己扛活，反而减轻根服务器负担
  • 看到"根DNS用迭代影响性能"——这是正常做法，不影响性能

知识点名称：DNS 记录类型（A记录 vs PTR记录）

核心定义/结论：

  • A记录：域名 → IP（正向解析）
  • PTR记录：IP → 域名（反向解析）
  • nslookup 能正查不能反查，原因是缺少 PTR 记录

典型题型：给出故障现象，问解决方法 → 答案是"创建PTR记录"

易错点：清除/刷新缓存、重启DNS服务都无法解决缺少PTR记录的问题

知识点名称：Linux DNS 配置文件

核心结论：/etc/resolv.conf 是 DNS 配置文件，包含 DNS 服务器地址和域名搜索顺序

易错点：/etc/hostname 只存主机名；/dev/ 目录是硬件设备目录，DNS配置不在此处

二、IPv6

知识点名称：IPv6 基本特性

核心结论：

  • 地址长度 128 位（IPv4 是 32 位）
  • 三种寻址方式：单播、组播、任播（无广播）
  • 首部比 IPv4 更简单
  • 一台主机可拥有多个 IPv6 地址

典型题型：判断关于 IPv6 的说法哪个正确

易错点：

  • 误以为有广播（IPv6 废除了广播）
  • 误以为每台主机只有唯一一个 IPv6 地址

知识点名称：IPv6 链路本地地址生成

核心结论：前缀 FE80::/10 + MAC 地址（经 EUI-64 转换为接口标识符）= 链路本地地址

易错点：不是 IPv4 地址、不是主机名、不是随机字符串；随机字符串是隐私扩展机制，非标准流程

三、IP 协议与 QoS

知识点名称：DiffServ 区分服务

核心结论：DiffServ 使用 IPv4 头部的"服务类型（ToS）"字段承载 DS 码点，路由器据此调度转发

易错点：TTL（生存期）、段偏置值、源地址均与 QoS 标记无关

知识点名称：Internet 核心交换方式

核心结论：Internet 核心采用分组交换（数据拆包 → 独立路由 → 目的地重组）

四种交换方式区别：

  • 分组交换：拆包独立走，Internet 用
  • 电路交换：占专线，电话网用
  • 虚电路：逻辑专线，早期 X.25 用
  • 消息交换：整报文存储转发，延迟高

四、传输层协议

知识点名称：TCP/UDP 与端口号

核心结论：

  • TCP 和 UDP 是传输层协议
  • 端口号的作用是对应用层进程寻址（IP找电脑，端口找程序）
  • 流量控制、三次握手是 TCP 的功能，不是端口号的作用

易错点：ACL 过滤是设备配置策略，与端口号本身作用无关

五、应用层协议

知识点名称：电子邮件协议与端口

核心结论：

协议用途端口
SMTP发邮件25
POP3收邮件（下载到本地）110
IMAP在线管理邮件143
HTTP网页80
HTTPS加密网页443

易错点：Telnet 端口是 23，是干扰项

知识点名称：HTTP vs HTTPS

核心结论：

  • HTTPS = HTTP + SSL/TLS 加密，端口 443
  • HTTP 明文传输，端口 80
  • 涉及支付、密码、隐私的场景必须用 HTTPS

知识点名称：安全电子邮件协议

核心结论：

  • S/MIME：安全邮件协议（加密+签名+完整性+认证）
  • PGP：邮件内容加密与签名
  • MIME：只是邮件格式标准，与安全无关
  • SSL/HTTPS：传输层/网页安全，不专属于邮件

易错点：MIME ≠ S/MIME，MIME 不提供任何安全功能

六、网络安全协议

知识点名称：各安全协议所在层级

核心结论：

协议所在层
HTTPS应用层
SSL/TLS传输层（介于传输层与应用层之间）
IPSec网络层
L2TP数据链路层
PAP数据链路层

易错点：IPSec 是网络层，不是应用层；L2TP 名字含"L2"，不在应用层

知识点名称：SSL 协议特性

核心结论：SSL 提供保密性、可靠性、完整性，但不提供不可抵赖性

不可抵赖性由数字签名提供，SSL 本身不包含此功能

知识点名称：Kerberos 认证

核心结论：

  • 使用 KDC（密钥分发中心）发放票据，不使用 CA
  • KDC = AS（验身份）+ TGS（发票据）
  • KDC 保存所有用户账号和密码
  • 使用时间戳防止重放攻击

易错点：Kerberos 找 KDC 要票，CA 是 PKI/HTTPS 体系的概念，两者不能混用

七、网络设备与数据链路层

知识点名称：OSI 各层对应设备

核心结论：

层设备
物理层集线器、中继器
数据链路层交换机、网桥
网络层路由器

知识点名称：以太网交换机 MAC 地址表

核心结论：

  • 初始 MAC 地址表为空
  • 通过读取帧的源 MAC 地址学习表项（不是目的地址）
  • 没有匹配表项时洪泛（广播到所有端口），不是丢弃
  • 表项动态维护，会老化删除

易错点：C 选项"读取目的地址学习"是高频陷阱，实际是源地址

知识点名称：以太网编码方式

核心结论：以太网使用曼彻斯特编码（每 bit 中间强制跳变，自带时钟同步）；差分曼彻斯特编码用于令牌环网；循环码是差错检测编码，不用于物理层传输

知识点名称：OSI 安全服务分布

核心结论：OSI 七层中，会话层是唯一未定义安全服务的层次；其余六层均可提供相应安全机制

八、DHCP 协议

知识点名称：DHCP 工作原理与报文类型

核心结论：

  • 客户端通过广播自动寻找 DHCP 服务器，无需手动指定地址
  • IP 地址由服务器分配，不是客户端自选
  • 一个网络可以有多台 DHCP 服务器（地址池不重叠）
  • DHCP 服务默认不开启，需手动启用

报文类型：

报文发送方含义
DhcpDiscover客户端广播寻找服务器
DhcpOffer服务器提供可用 IP
DhcpRequest客户端请求使用该 IP
DhcpAck服务器确认分配
DhcpDecline客户端拒绝（IP已被占用）
DhcpNack服务器拒绝客户端请求

易错点：DhcpDecline 是客户端发的，DhcpNack 是服务器发的，方向相反

九、信号与编码

知识点名称：奈奎斯特采样定理

核心公式：采样频率 ≥ 信号最高频率 × 2，即信号最高频率 ≤ 采样频率 ÷ 2

典型题型：给出采样频率，求信号最高频率上限 → 直接除以 2

十、新技术

知识点名称：5G 网络切片技术

核心结论：网络切片将一张物理网络切分为多张逻辑独立的虚拟网络，每张切片端到端独立，互不影响；SDN 是支撑技术，不是切片本身

知识点名称：WiFi 认证方式安全等级

安全等级从低到高：开放式 < WEP（RC4，有漏洞）< WPA（TKIP）< WPA2（AES，最安全）

推荐复习顺序

  1. OSI 七层模型 + 各层设备/协议对应（基础框架，其他知识点都依赖它）
  2. TCP/UDP + 端口号（传输层核心，高频）
  3. HTTP/HTTPS + 常用端口号（应用层最常考）
  4. DNS 解析机制（递归/迭代 + A/PTR记录）
  5. IPv6 基本特性
  6. 安全协议层级（IPSec/SSL/HTTPS/PAP/L2TP）
  7. SSL 特性 + Kerberos 认证
  8. 电子邮件协议（SMTP/POP3/IMAP/S/MIME）
  9. DHCP 报文类型
  10. 交换机 MAC 地址表 + 以太网编码
  11. 分组交换 + 奈奎斯特定理
  12. DiffServ + 5G 切片 + WiFi 认证（了解即可，超纲内容放最后）

综合布线系统 · 结构化知识要点清单

一、知识点名称

综合布线系统（结构化布线系统）六大子系统

二、核心定义与结论

综合布线系统将建筑物内的网络、电话、数据等线路统一规划，分为六个子系统：

子系统核心功能记忆关键词
工作区子系统终端设备 → 信息插座桌面最后一米
水平子系统信息插座 → 本层配线间（连接工作区与干线）同层水平铺线
干线子系统各楼层设备间之间垂直互连楼层间主干
管理子系统配线架、跳线板，负责线路调配每层分拣台
设备间子系统放置交换机、服务器等核心设备楼内总机房
建筑群子系统楼与楼之间的室外线缆连接跨楼干线

层级关系（从宏观到微观）：

```

建筑群 → 设备间 → 干线 → 管理 → 水平 → 工作区

```

三、典型题型与解题要领

题型：给出某子系统的功能描述，判断是哪个子系统（或反向）

解题要领只有一条：抓住每个子系统的位置特征

  • 问"连接哪两个子系统" → 先定位它在层级链中的位置，上下各是谁
  • 问"由什么设备组成" → 设备间 = 有大型设备；管理 = 配线架跳线
  • 问"实现什么互连" → 垂直/楼层间 = 干线；跨楼 = 建筑群；同层 = 水平

水平子系统是高频考点，记住这个结构：

```

干线子系统

↕

水平子系统 ← 夹在中间，所以"连接干线与工作区"

↕

工作区子系统

```

四、易错点与注意事项

最容易混淆的三组：

  1. 水平 vs 工作区
  • 水平：插座 → 配线间（在墙里走线）
  • 工作区：终端 → 插座（在桌面可见）
  • 口诀：看得见摸得着的那段 = 工作区
  1. 水平 vs 干线
  • 水平：同一楼层，横向延伸
  • 干线：跨楼层，纵向贯穿
  • 口诀：水平横，干线竖
  1. 管理 vs 设备间
  • 管理：配线架、跳线，负责"调度"
  • 设备间：交换机、服务器，负责"运算"
  • 口诀：有交换机的是设备间，只有配线架的是管理

常见陷阱：

  • 选项说"交叉连接设备、集线器、交换机" → 不是水平，是设备间/管理
  • 选项说"各楼层之间互连" → 不是水平，是干线

五、推荐复习顺序

  1. 先背六个名称，建立整体框架
  2. 记层级链：建筑群 → 设备间 → 干线 → 管理 → 水平 → 工作区
  3. 重点攻克水平、干线、工作区三个高频混淆项
  4. 用排除法练习：看到选项描述，先排掉明显不符的，再定位
  5. 做2~3道真题验证，重点看错误选项的干扰逻辑

> 考试权重：了解级别，不考细节参数，只考子系统功能对应关系，5分钟能拿稳。

知识点名称

RAID 磁盘阵列容量计算（重点：RAID 5）

核心定义/结论

RAID（独立磁盘冗余阵列）通过多块硬盘组合提升性能或可靠性，不同级别的容量利用率不同：

RAID 级别最少盘数可用容量公式冗余能力
RAID 02N × 单块容量无，坏一块全丢
RAID 121 × 单块容量允许坏 N/2 块
RAID 53(N-1) × 单块容量允许坏 1 块

RAID 5 关键规则：

  • 校验信息分散存储在所有盘上，等效牺牲一块盘的容量
  • 各盘容量不一致时，以最小容量为基准统一计算

典型题型与解题要领

题型：给定 N 块硬盘（容量相同或不同），求 RAID 5 可用容量

解题步骤：

  1. 判断各盘容量是否一致
  2. 不一致则取最小容量作为统一基准
  3. 套公式：可用容量 = (N - 1) × 基准容量

示例：

  • 3 × 80G → (3-1) × 80G = 160G
  • 2 × 80G + 1 × 40G → 基准取 40G → (3-1) × 40G = 80G

易错点与注意事项

  • 容量不一致时忘记取最小值，直接用大容量计算，导致结果偏大
  • 把 RAID 5 的公式套成 RAID 0（忘记减 1）
  • RAID 1 只有 2 块盘时，可用容量是单块容量，不是两块之和，容易和 RAID 0 混淆
  • RAID 5 最少需要 3 块盘，2 块盘无法组建

推荐复习顺序

  1. 先理解 RAID 0 / 1 / 5 各自的设计目的（性能 / 镜像 / 分散校验）
  2. 记住三个容量公式，重点记 RAID 5 的 (N-1) 逻辑
  3. 掌握"容量不一致取最小"这条规则
  4. 做 2~3 道混合容量的计算题巩固
  5. 最后横向对比三种 RAID 的适用场景，备考简答/案例题

通信原理 · 结构化知识点清单

知识点名称

香农公式与信道容量

核心定义/结论

香农公式：C = B × log₂(1 + S/N)

符号含义单位
C信道容量（最大传输速率）bps
B信道带宽Hz
S/N信噪比（信号功率/噪声功率）无量纲

核心结论：信道容量由带宽和信噪比共同决定，两者正相关。提高任意一个，C 都会增大；两个同时提高，效果最优。

典型题型与解题要领

题型：给出香农公式背景，问如何提高信道传输速率

解题要领：

  • 直接套公式逻辑：C 变大 → B 要大、S/N 要大
  • 选项中出现"两个都提高"的，优先选
  • 不需要计算，只需判断变量方向（增/减）

解题口诀：路宽信号纯，数据跑得快

易错点与注意事项

  • 混淆"带宽"概念：在通信原理中带宽单位是 Hz（频率范围），不是 bps（比特率）。日常说的"带宽100M"其实是速率，考试语境要区分
  • 信噪比方向搞反：信噪比越高 = 噪声越小 = 信号越纯净 = 越好。不要误以为"噪声多才能传得快"
  • 选项陷阱：D 选项"减少带宽+提高信噪比"看起来有一半对，但带宽减少会直接压低 C 的上限，整体仍是负效果
  • 奈奎斯特定理 vs 香农公式：两者都涉及传输速率，但奈奎斯特针对无噪声信道，香农针对有噪声信道，不要混用

推荐复习顺序

  1. 先理解信道容量的概念（信道能跑多快的上限）
  2. 记住香农公式的三个变量及其关系
  3. 对比奈奎斯特定理（无噪声场景），搞清两者适用条件
  4. 做选项判断类题目，练习变量方向分析
  5. 最后延伸到实际应用：为什么 5G 要用更高频段（更大带宽）+ 更好的信号处理（提高信噪比）

官方解析

本题考察的是DNS 解析原理。

在DNS解析过程中，主要有两种查询方式：递归查询和迭代查询。

  1. 递归查询：由发起查询的DNS服务器（如本地域名服务器）完全处理查询过程。如果它没有所需的结果，它会代表客户端发起后续查询，直到得到最终答案或者返回失败。此方式会增加该DNS服务器的负担，因为它需要继续向其他服务器发起查询请求。
  2. 迭代查询：如果查询的DNS服务器无法提供结果，它会返回一个指向下一个合适DNS服务器的地址，查询过程由请求方继续完成。这种方式通常会降低服务器负担，因为每个DNS服务器只需要提供其职责范围内的信息，并不负责完成整个查询过程。

此图中中介域名服务器采用递归查询，根域名也是根域名服务器采用递归查询。但是假如根域名服务器如果采用递归查询，会代替客户端继续查询并最终返回结果，这会导致根域名服务器的负担增加。根域名服务器主要负责顶级域名的解析，不应该在此过程中参与递归查询，通常采用迭代查询。

B选项：根域名服务器采用迭代查询，影响了性能：根域名服务器通常采用迭代查询，不会影响性能，所以不选。

C选项：中介域名服务器采用迭代查询，加重了根域名服务器负担：中介域名服务器在此图中采用递归查询，而不是采用迭代查询，描述错误，所以不选。

D选项：中介域名服务器采用递归查询，加重了根域名服务器负担：如果中介域名服务器采用递归查询，它将代表客户端完成查询，最终返回结果。这会将中介服务器的负担增加，同时减少根域名服务器的负担。描述错误，所以不选。

因此，选择选项 A 。

官方解析

本题考察的是IPv6 的无状态地址自动配置机制中的链路本地地址生成方法。

IPv6 中，链路本地地址（Link-Local Address）用于本地链路上的通信，不可路由。其地址前缀固定为 1111 1110 10（即 FE80::/10），后面跟一系列 0，然后是接口标识符。

在客户机上运行 nslookup 查询某服务器名称时能解析出 IP 地址，查询IP地址时却不能解析出服务器名称，解决这一问题的方法是（）。

子题1

参考答案：C

官方解析

本题考察的是DNS 正向解析与反向解析的原理。

在 DNS 系统中，正向解析是根据域名查找对应的 IP 地址，这依赖于 A 记录；反向解析是根据 IP 地址查找对应的域名，这依赖于 PTR（Pointer）记录。

A选项 清除 DNS 缓存：只能清除本地缓存记录，不会解决服务器没有反向记录的问题，错误。

B选项 刷新 DNS 缓存：与清除缓存类似，仅更新缓存内容，无法生成不存在的反向解析记录，错误。

C选项 为该服务器创建 PTR 记录：PTR 记录是反向 DNS 查询所需的记录，没有此记录就无法通过 IP 查询出域名，因此这是根本解决办法，正确。

D选项 重启 DNS 服务：只能重启 DNS 进程，不会自动添加缺失的 PTR 记录，错误。

因此，本题答案为 C。

如果发送给 DHCP 客户端的地址已经被其他 DHCP 客户端使用，客户端会向服务器发送（）信息包拒绝接受已经分配的地址信息。

子题1

参考答案：C

官方解析

本题考察的是DHCP 协议中的报文类型与作用。

DHCP（Dynamic Host Configuration Protocol）在为客户端分配 IP 地址的过程中，会使用多个不同类型的消息进行交互。

A选项 DhcpAck：由 DHCP 服务器发送，用于确认客户端请求并分配 IP 地址，表示地址分配成功，错误。

B选项 DhcpOffer：由 DHCP 服务器发送，向客户端提供可用 IP 地址的“报价”，错误。

C选项 DhcpDecline：由 DHCP 客户端发送，如果客户端在收到 DHCP Ack 后通过冲突检测发现 IP 已被占用，就会向服务器发送 DhcpDecline 报文拒绝使用该地址，这是正确答案。

D选项 DhcpNack：由 DHCP 服务器发送，用于拒绝客户端的请求或通知客户端租约已失效，与客户端拒绝地址的场景不同，错误。

因此，本题答案为 C。

子题1

官方解析

本题考察的是TCP协议中端口号的作用，属于传输层相关的基础知识点。

C选项建立连接：虽然TCP协议确实需要建立连接，但这指的是三次握手过程，与“端口号”的作用无直接对应，因此该选项错误。

D选项对应用层进程的寻址：端口号的核心作用就是用于标识主机上的具体应用进程，传输层协议通过端口号将接收到的数据交付给对应的应用程序，这是正确选项。

Web 页面访问过程中，在浏览器发出 HTTP 请求报文之前不可能执行的操作是（）。

子题1

参考答案：C

官方解析

本题考察的是网络通信过程及协议工作顺序的基本概念。

浏览器访问 Web 页面时，会先进行域名解析（查询本机缓存或向 DNS 服务器请求），接着在本地网络中可能会通过 ARP 获取网关 MAC 地址，然后建立 TCP 连接，最后才会发出 HTTP 请求报文。因此，在发出 HTTP 请求报文之前，与 HTTP 层直接交互的操作是无法进行的。

A选项 查询本机 DNS 缓存：这是域名解析的第一步，可以在 HTTP 请求之前执行，正确。

B选项 发起 DNS 请求：如果本地缓存没有命中，会向 DNS 服务器查询 IP 地址，这个过程也在 HTTP 请求之前执行，正确。

C选项 发送 HTTP 请求信息：HTTP 请求报文是在建立 TCP 连接并完成网络底层准备后才会发送的，因此在发出 HTTP 请求报文之前，不可能提前执行此操作，正确答案。

D选项 发送 ARP 协议广播数据包：当目标 IP 在本地网络中或需要找到网关时，ARP 请求会在 HTTP 报文发送前进行，以便获取 MAC 地址，正确。

因此，选项 C 正确。

D选项 非封闭性网：局域网是封闭性网，它的网络通常在一个有限的地理范围内，且大多数局域网是通过专用的设备和协议来进行管理和控制的。局域网的访问通常是受到限制的，外部设备需要经过认证才能接入网络。因此，局域网通常是封闭性的，不是开放或非封闭性网络。因此，D选项是错误的。

第38题（题号：32）

网络协议 难度：0

处理一个连续时间信号，对其进行采样的频率为3kHz，要不失真的恢复该连续信号,则该连续信号的最高频率可能是为（）。

子题1

参考答案：B

官方解析

本题考察的是奈奎斯特采样定理（Nyquist Sampling Theorem）。

根据该定理：为避免混叠失真，采样频率必须大于或等于信号最高频率的两倍，即：

采样频率 ≥ 2 × 信号的最高频率

本题中，采样频率为 3kHz，那么信号的最高频率不能超过：

3kHz ÷ 2 = 1.5kHz

A选项6kHz：错误，明显超过采样频率，不可能恢复。

B选项1.5kHz：正确，等于采样频率的一半，是不失真恢复的最大限值。

C选项3kHz：错误，采样频率本身，违反奈奎斯特条件。

D选项2kHz：错误，超过采样频率一半，也会引发混叠。

因此，正确答案为 B。

第43题（题号：59）

通信原理 难度：0

信道容量就是信道的最大传输速率。香农公式表示，要提高信道的信息传输速率可以采用（）的方法来实现。

子题1

参考答案：A

官方解析

本题考察的是香农公式与信道容量的关系。

香农在《通信的数学理论》中提出的著名香农公式为：C = B × log₂(1 + S/N)，

其中，C 为信道容量（bps），B 为信道带宽（Hz），S/N 为信噪比。

该公式说明：信道的最大信息传输速率C取决于信道的带宽B和信噪比S/N。若要提升C，可以从以下两个方面入手：

提高带宽B：增加信道可以承载的频率范围，直接提高数据传输速率。

提高信噪比S/N：信噪比越高，说明有用信号越强、噪声越弱，也会提升传输的有效性，从而提升传输速率。

A选项提高带宽、提高信噪比：完全符合香农公式的提升条件，是正确选项。

B选项提高带宽、减少信噪比：信噪比降低会导致传输误码率升高，降低信道容量，因此不正确。

C选项减少带宽、减少信噪比：两项均对信道容量有负面影响，更不可能提高传输速率，错误。

D选项减少带宽、提高信噪比：虽然信噪比提高有益，但减少带宽会限制传输能力，整体效果不如选项A，因此也不正确。

因此，选项 A 正确。
