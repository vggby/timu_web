关系数据库 · 结构化知识点清单

一、范式理论（NF）

知识点名称：关系范式判断与规范化

核心定义/结论：

  • 1NF：属性原子性，每格只有一个值
  • 2NF：消除非主属性对候选码的部分依赖（单属性主键天然满足）
  • 3NF：消除非主属性对候选码的传递依赖（A→B→C 型）
  • BCNF：所有决定因素都是候选码

典型题型与解题要领：

  • 给定 U 和 F，判断关系是几范式
  • 步骤：① 找候选码 → ② 看是否有部分依赖（判断2NF）→ ③ 看是否有传递依赖（判断3NF）
  • 单属性主键 → 自动满足2NF，只需判断是否有传递依赖

易错点与注意事项：

  • 部分依赖只在组合主键时才可能出现
  • 传递依赖 A→B→C 中，B 必须是非主属性才构成传递依赖
  • 存在部分依赖 → 最多1NF；存在传递依赖 → 最多2NF

二、候选码与属性闭包

知识点名称：候选码判定 + 属性闭包计算

核心定义/结论：

  • 候选码 = 能推出全部属性的最小属性组合
  • 属性闭包 X⁺ = 从 X 出发，沿函数依赖能推出的所有属性集合
  • 入度为零的属性（没有任何依赖指向它）必须出现在候选码中

典型题型与解题要领：

  • 滚雪球法：初始集合 = X，反复扫描 F，把能推出的属性加入集合，直到不变为止
  • 有向图法：画出依赖图，找入度为零的节点，从它们出发验证能否遍历全图

易错点与注意事项：

  • 候选码要求最小性，A1 能推全集时，A1A2 不是候选码
  • 入度为零的属性必须全部进入候选码，缺一不可

三、Armstrong 公理系统

知识点名称：函数依赖推理规则

核心定义/结论：

规则名公式记忆口诀
自反律Y⊆X → X→Y整体推部分
增广律X→Y → XZ→YZ两边加料不变
传递律X→Y, Y→Z → X→Z接力棒传递
合并规则X→Y, X→Z → X→YZ同左边，右边打包
分解规则X→Y, Z⊆Y → X→Z大包拆小包

典型题型与解题要领：

  • 看题目描述，对应规则名称
  • 合并：同一个左边，右边合体
  • 分解：右边是子集，可以拆出来

易错点与注意事项：

  • 合并 vs 分解容易混：合并是"两条变一条"，分解是"一条变两条"
  • 传递律 vs 分解规则：传递律有 Y→Z 箭头，分解规则有 Z⊆Y 包含关系

四、关系分解（无损连接 + 保持函数依赖）

知识点名称：模式分解的性质判断

核心定义/结论：

  • 无损连接：分解后能拼回原表，判断条件 → 两子模式交集能函数决定某一边的差集
  • 保持函数依赖：原始 F 中每条依赖，在某个子模式中能完整体现（左右两边的属性都在同一个子模式里）

典型题型与解题要领：

  • 无损判断：计算 U1∩U2，看它能否推出 U1-U2 或 U2-U1
  • 保持依赖判断：逐条检查 F 中每个依赖，看左右属性是否都在某个子模式中

易错点与注意事项：

  • 无损 ≠ 保持依赖，两者独立判断，可以只满足其一
  • B→C 被分解后，若 B 和 C 分属不同子模式，则该依赖丢失

五、关系代数（选择、投影、连接）

知识点名称：关系代数操作与列编号

核心定义/结论：

  • σ（选择）= 筛行，对应 SQL WHERE
  • π（投影）= 留列，对应 SQL SELECT
  • ⋈（自然连接）= 按同名列对齐合并，去掉重复列
  • ×（笛卡尔积）= 暴力全排列拼表

自然连接列数公式：R列数 + S列数 - 公共列数

R×S 后列编号规则：R 的列先排，S 的列后排，从1开始连续编号

典型题型与解题要领：

  • 看到 π 下标数字 → 查位次表找列名
  • 看到 σ 下标 m=n → 第m列 = 第n列
  • 自然连接转 SQL → 公共列全部写等值条件，用 AND 连接

易错点与注意事项：

  • 自然连接条件用 AND，不是 OR
  • 同名列在 SQL 中需加表名前缀消歧（如 R.C）
  • 笛卡尔积后列编号不要数错，R 先 S 后

六、查询优化

知识点名称：关系代数表达式的执行效率

核心定义/结论：

  • 核心原则：先筛选（σ），再连接（⋈），避免先做笛卡尔积（×）
  • 效率排序：先各自筛选再连接 > 先连接再筛选 > 先筛选再叉积 > 先叉积再筛选

典型题型与解题要领：

  • 找哪个表达式最先做了 σ，且用的是 ⋈ 而不是 ×
  • 口诀：选择越早越好，连接优于叉积

易错点与注意事项：

  • E2 类型（先各自筛选再连接）是标准最优写法
  • E3 类型（先叉积再筛选）是最差写法，中间结果最大

七、SQL 语法

知识点名称：外键约束、HAVING、SQL 基础

核心定义/结论：

  • 外键语法：FOREIGN KEY (列名) REFERENCES 目标表(列名)
  • HAVING 必须与 GROUP BY 连用，用于分组后过滤
  • WHERE 在分组前过滤行，HAVING 在分组后过滤组

典型题型与解题要领：

  • 外键题：认准 FOREIGN KEY + REFERENCES，方向是"我的列 → 别人的主键"
  • HAVING 题：看到"分组后筛选"→ 秒选 GROUP BY

易错点与注意事项：

  • Primary Key ≠ Foreign Key，不要混淆
  • HAVING 不能单独使用，必须有 GROUP BY

八、元组演算

知识点名称：元组演算表达式的理解与计算

核心定义/结论：

  • { t | 条件 } = 从关系中挑出满足条件的元组 t
  • ∃u = 存在一个 u 满足条件即可（存在量词）
  • ∀u = 所有 u 都要满足（全称量词）
  • t[n] = t 这行的第 n 列的值

典型题型与解题要领：

  • 翻译表达式为白话 → 逐行代入验证 → 选出满足条件的元组

易错点与注意事项：

  • ∃ 是"找到一个就行"，门槛低；∀ 是"每一个都要满足"，门槛高
  • 代入时注意列编号从1开始

九、数据库安全与完整性约束

知识点名称：完整性约束类型 + 安全机制

核心定义/结论：

  • 实体完整性：主键唯一且不为空
  • 参照完整性：外键值必须在被参照表的主键中存在
  • 用户定义完整性：业务规则自定义约束（如性别只能填男/女）
  • 存储过程：封装操作逻辑，隐藏表结构，供外部调用更新数据

典型题型与解题要领：

  • 看到"固定枚举值/业务规则" → 用户定义完整性
  • 看到"封装+更新+隐藏结构" → 存储过程

易错点与注意事项：

  • 视图能隐藏结构但不擅长更新数据，不要选视图
  • 触发器是被动响应，不能被主动调用

十、数据库设计阶段

知识点名称：数据库设计四阶段

核心定义/结论：

阶段主要任务
需求分析收集业务需求
概念设计画 E-R 图
逻辑设计定表结构、规范化/反规范化 ← 考点
物理设计建索引、定存储结构

典型题型与解题要领：

  • 反规范化在逻辑设计阶段进行，秒选

易错点与注意事项：

  • 物理设计 ≠ 反规范化，这是最常见干扰项

十一、派生属性

知识点名称：关系模式设计中的派生属性处理

核心定义/结论：

  • 派生属性 = 能由其他属性计算得出的属性，不应存入数据库
  • 典型例子：年龄（可由出生日期计算）、总价（可由单价×数量计算）

典型题型与解题要领：

  • 找出能被计算出来的属性，从模式中删除它

易错点与注意事项：

  • 出生日期不是派生属性（无法计算），年龄才是

推荐复习顺序

  1. 范式理论（1NF/2NF/3NF/BCNF）— 高频，必须熟练
  2. 候选码与属性闭包 — 高频，配合范式一起练
  3. Armstrong 公理系统 — 中频，记住六条规则名称和公式
  4. 关系分解（无损+保持依赖）— 高频，常与范式组合出题
  5. 关系代数（σ/π/⋈/×）— 高频，重点练列编号和 SQL 转换
  6. 查询优化 — 中频，记住"先筛后连"原则
  7. SQL 语法（外键/HAVING）— 低频，认识语法即可
  8. 完整性约束与安全机制 — 低频，送分题，记住三类约束
  9. 数据库设计阶段 — 低频，送分题
  10. 元组演算、派生属性 — 低频，了解即可

特殊数据库系统 · 结构化知识点清单

知识点名称

特殊数据库系统（嵌入式数据库、分布式数据库、数据仓库、网络数据库）

核心定义/结论

嵌入式数据库（EDBMS）

轻量级数据库，嵌入设备内部（手机、车载、PDA），本地运行，不依赖网络。四大特征：轻量小巧、支持实时处理、只提供本机接口、支持多线程并发。

分布式数据库

数据分散在多个节点，用户感知如同单一数据库。核心概念有两组：

四种透明性：

  • 分片透明 → 不用管数据怎么切割
  • 位置透明 → 不用管数据在哪台机器
  • 复制透明 → 不用管数据有几个副本
  • 逻辑透明 → 不用管对方用什么数据模型/语言

四层模式结构（从上到下）：

  • 全局外模式 → 对外暴露的用户视图
  • 全局概念模式 → 整体逻辑蓝图，用户感知不到分布
  • 分片模式 → 描述数据如何切割
  • 分布模式 → 描述切片放在哪台机器

两阶段提交（2PC）：

  • 表决阶段：协调者询问所有参与者"能提交吗"，参与者准备但不提交
  • 执行阶段：全部同意则提交，有一个拒绝则全部回滚

数据仓库

面向决策分析的数据集合，四大特点：面向主题、集成性、相对稳定性（非易失性）、反映历史变化。

网络数据库（NDB）

基于4G/5G，数据存在远程服务器，客户端轻量。三部分组成：客户端、通信协议、远程服务器。

典型题型与解题要领

题型1：特征判断（选"不正确的"）

题号7（嵌入式）、题号8（NDB）均为此类。

要领：先在脑中列出该系统的正确特征清单，逐项比对，找出与事实不符的选项。嵌入式数据库支持多线程是高频陷阱；NDB数据在远端不在本地文件是核心。

题型2：概念对号入座（选"哪种透明/哪种特点"）

题号4、7（透明性）、题号6（数据仓库特点）均为此类。

要领：抓题干关键词直接映射：

  • "物理位置" → 位置透明
  • "数据模型/局部场地" → 逻辑透明
  • "副本/备份" → 复制透明
  • "切割/分块" → 分片透明
  • "长期保留/很少修改删除" → 相对稳定性
  • "整体逻辑结构/感觉不到分布" → 全局概念模式

题型3：协议阶段识别

题号9（2PC）。

要领：2PC = 表决+执行；2PL（两阶段锁）= 扩展+收缩，两者极易混淆，看到"扩展/收缩"直接排除。

易错点与注意事项

  • 嵌入式数据库支持多线程并发，"不支持"是错误说法，这是最高频的陷阱
  • 2PC（提交协议）和2PL（锁协议）名字相近，阶段名称完全不同，必须区分
  • 分片透明和位置透明容易混淆：分片关注结构（怎么切），位置关注地点（放哪里）
  • 全局概念模式和全局外模式容易混淆：概念模式是整体蓝图，外模式是对外视图
  • NDB的数据在远程服务器，不是本地文件，D选项描述的是文件型数据库的特征
  • 数据仓库"相对稳定性"≠完全不变，定期加载刷新是允许的，只是很少修改删除

推荐复习顺序

  1. 数据仓库四大特点（最简单，纯记忆，送分）
  2. 分布式数据库四种透明性（出题频率最高，关键词映射练熟）
  3. 分布式数据库四层模式结构（理解层次关系后记忆）
  4. 嵌入式数据库特征（重点记"支持多线程"这一反直觉点）
  5. 2PC两阶段提交（同时对比2PL，防混淆）
  6. NDB网络数据库（最后补充，区分三种数据库类型即可）

数据库设计知识点结构化要点清单

知识点一：数据库转储方式

核心定义/结论

转储 = 将数据库数据复制到外部存储介质，用于故障恢复。两个维度正交组合：

  • 静态 vs 动态：转储期间是否允许事务并发运行
  • 全局 vs 增量：转储全部数据 vs 仅转储上次以来变化的数据

四种组合：静态全局、静态增量、动态全局、动态增量

典型题型与解题要领

题型：给出场景描述，选择合适的转储方式

解题两步走：

  1. 看"有无正在运行的事务" → 有事务 = 动态，无事务可用静态
  2. 看"转储范围" → 全部数据 = 全局，仅变化数据 = 增量

口诀：有人在用不能停 → 动态；全部数据都要拿 → 全局

易错点与注意事项

  • 动态增量也允许事务并发，但只备份变化数据，不满足"全部转储"要求，容易误选
  • 静态方式必须等所有事务结束才能执行，题干只要出现"有正在运行的事务"，静态选项直接排除

知识点二：E-R 图合并冲突

核心定义/结论

合并多个局部 E-R 图时，存在三类冲突：

冲突类型本质典型表现
属性冲突同一属性的值域/类型不一致A部门年龄存整数，B部门存"青年/中年"
命名冲突名字打架同名异义（都叫"编号"含义不同）或异名同义（"员工"vs"职员"是同一个）
结构冲突同一现实对象，画法不同A部门把培训师画成独立实体，B部门把它作为员工的属性

典型题型与解题要领

题型：给出两个部门的 E-R 图描述，判断冲突类型并选择合并方案

判断冲突三步走：

  1. 名字有没有打架？→ 命名冲突
  2. 同一字段值/范围不一样？→ 属性冲突
  3. 同一个东西，一边是实体框，一边是属性？→ 结构冲突

结构冲突的标准解法：将子实体的关键属性（如职称）并入父实体，删除多余实体

易错点与注意事项

  • 结构冲突解决时，选项 C（明确加入职称属性）优于选项 D（笼统说"并入所有属性"），因为 C 更精准指出了合并的核心字段
  • "实体冲突"不是标准分类，出现即排除
  • 培训师是员工的子集，合并后用职称属性区分，不能直接删除培训师实体而不保留其属性信息

推荐复习顺序

  1. E-R 图基础概念（实体、属性、联系）
  2. E-R 图合并冲突三类型（属性/命名/结构）及解决方法
  3. 数据库转储四种方式的定义与区别
  4. 结合真题场景做两步排除法练习
  5. 重点区分动态增量 vs 动态全局的适用场景（高频混淆点）

数据库基本概念 · 结构化知识点清单

一、数据库三级模式结构

核心定义

数据库系统采用三级模式体系：外模式、概念模式（模式）、内模式，通过两级映射实现数据独立性。

模式别名描述对象面向对象
外模式子模式、用户模式局部数据的逻辑结构用户/应用程序
概念模式模式、逻辑模式全局数据的逻辑结构、完整性、安全性数据库管理员
内模式物理模式、存储模式数据的物理存储方式、索引、文件组织系统底层

典型题型与解题要领

  • 题目出现"用户视图"、"局部数据"、"某一应用" → 选外模式
  • 题目出现"完整性"、"安全性"、"全局逻辑结构" → 选概念模式
  • 题目出现"索引"、"聚簇"、"物理存储"、"文件组织" → 选内模式

易错点

  • "物理模式"、"用户模式"不是标准术语，出现即为干扰项
  • "逻辑模式"是概念模式的别称，描述的是全局而非局部
  • 聚簇索引改变的是内模式，不是模式（模式只管逻辑结构）

二、数据库范式

核心定义

范式是关系模式规范化的级别，每升一级消除一种"坏依赖"。

范式消除的依赖记忆关键词
1NF字段不可再分（原子性）原子化
2NF消除部分依赖不偷懒（不能只靠半个主键）
3NF消除传递依赖不绕路（A→B→C 这种链条）
BCNF所有决定因素都是候选键加强版3NF
4NF消除多值依赖不堆多值

口诀：一原二部三传递，BC候选四多值

典型题型与解题要领

  • 给出函数依赖，判断属于哪个范式：先看有无部分依赖，再看有无传递依赖
  • 有传递依赖（A→B→C，B非主键）→ 最高只满足2NF
  • 单属性候选键不存在部分依赖，直接从是否有传递依赖开始判断

易错点

  • 多值依赖由4NF消除，不是3NF或BCNF
  • 高范式包含低范式（满足3NF必然满足2NF）
  • 单码（候选键只有一个属性）时不存在部分依赖，自动满足2NF

三、事务ACID特性

核心定义

事务是数据库不可分割的逻辑工作单位，具有四个特性：

特性含义记忆
原子性（A）要么全做，要么全不做不可再分
一致性（C）事务前后数据库状态一致总量不变
隔离性（I）多事务并发互不干扰各做各的
持久性（D）提交后永久保存，断电不丢永久生效

典型题型与解题要领

  • 问"不属于事务特性的是" → 找不是事务自身性质的选项
  • 并发性是数据库系统的能力，不是事务本身的特性，出现即选

易错点

  • 并发性经常作为干扰项出现，务必排除
  • 隔离性容易和并发性混淆：隔离性是事务的特性，并发性是系统的特性

四、关系代数：笛卡尔积与自然连接

核心定义

操作结果行数结果列数特点
笛卡尔积 R×Sm×nR列数+S列数两两配对，无条件组合
自然连接 R⋈S不定R列数+S列数-同名列数同名列做连接条件，去除重复列

典型题型与解题要领

  • 笛卡尔积元组数：直接用乘法，R有m行、S有n行 → m×n
  • 自然连接列数：套公式 R列数 + S列数 - 同名列数
  • 自然连接行数：只保留同名列值相等的行（题目一般不考行数计算）

易错点

  • 笛卡尔积是乘法不是加法，m+n是错误答案
  • 自然连接会去掉重复的同名列，不是简单拼接

五、候选键与属性闭包

核心定义

  • 候选键：能唯一标识关系中每个元组的最小属性组合
  • 属性闭包 X⁺：从属性集X出发，利用函数依赖能推导出的所有属性集合

典型题型与解题要领

三步判断法：

  1. 对每个候选属性（组合）计算闭包
  2. 闭包等于全属性集 → 是超键
  3. 去掉任意一个属性后闭包不再是全集 → 是候选键（最小性验证）

闭包计算步骤：初始化为X本身 → 扫描所有函数依赖 → 左边在闭包内则把右边加入 → 重复直到不再扩展

易错点

  • 候选键可能有多个，不要找到一个就停
  • 验证最小性：必须确认去掉任意一个属性后就不够用了
  • 没有任何函数依赖以某属性开头 → 该属性必须出现在候选键中（无法被推导出来）

```
│ │

│ 1NF → 2NF → 3NF （一级比一级严格） │
```

1NF「一格一值」

> 每个格子里只能填一个值，不能填"北京/上海"这种

✅ 只要是正经的关系表，基本都满足，门槛最低

2NF「完全靠主键」

> 非键属性必须完全依赖主键，不能只依赖主键的一部分

顾名思义记忆： "2NF = 二才能上，半个主键不够用"

什么时候会违反？ 主键是组合键（两列以上）时才可能出问题

```

反例：

表(学号, 课程号, 成绩, 学生姓名)

主键 = (学号+课程号)

但 学号 → 学生姓名 ← 只靠半个主键就能确定姓名

❌ 违反2NF

```

单属性主键 = 天然满足2NF（因为主键只有一列，不存在"部分依赖"）

3NF「直接靠主键，不走弯路」

> 非键属性必须直接依赖主键，不能通过另一个非键属性"绕弯"

顾名思义记忆： "3NF = 三角关系不允许，A→B→C 这种传递要消灭"

```

反例：

表(学号, 系名, 系主任)

学号 → 系名 → 系主任 ← 传递依赖！

系主任是靠系名确定的，不是直接靠学号

❌ 违反3NF

```

🔗 无损连接 vs 保持函数依赖

无损连接「分开再合，数据不丢」

顾名思义： "无损 = 分解后还能拼回原来的表，一行不多一行不少"

判断方法（记这个口诀）：

```

→ 就是无损连接

本题：

R1(A,B) R2(A,C)

公共列 = {A}

A→B ✅（A能决定R1的独有列B）

→ 无损连接！

```

顾名思义： "保持依赖 = 原来表里的所有规则，在分解后的小表里还能查到"

```

分解后：

R1(A,B) 能体现 A→B ✅

R2(A,C) 能体现 A→C ✅

但 B→C 在哪个子表里都找不到！

R1没有C，R2没有B，B和C被分开了

❌ 不保持函数依赖
```

1. 自然连接（Natural Join）

> 顾名思义：两张表"自然而然"地按同名列拼在一起，重复的列只保留一份

```

R(A, B, C, D) S(B, C, E, F)

↓ ↓

同名列是 B 和 C ← 找到"同名兄弟"

↓

↓
```

> 顾名思义：像"投影仪"一样，只把你想要的列打出来，其余的列遮住

```

π₁,₃,₅,₆ → 取第1、3、5、6列

┌────┬────┬────┬────┬────┬────┐

│ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │

│ A │ B │ C │ D │ E │ F │

└────┴────┴────┴────┴────┴────┘

取 1,3,5,6 → A, C, E, F

```

> 顾名思义：像"筛子"一样，只把满足条件的行留下来

第一问：自然连接后有几列？答案 B（6列）

```

R(A, B, C, D) ⋈ S(B, C, E, F)

步骤：

  1. 找同名列：B 和 C（两张表都有）
  2. 合并，同名列只留一份
  3. 结果：A, B, C, D, E, F = 6列

记忆：4 + 4 - 2(重复) = 6

```

第二问：SELECT 后面选哪些列？答案 A（A, R.C, E, F）

```

π₁,₃,₅,₆ 对应 → 第1列A、第3列C、第5列E、第6列F

⚠️ 注意：C 在 R 和 S 里都有，SQL 里必须写清楚是谁的
```

第三问：WHERE 条件怎么写？答案 B

```

自然连接 = 笛卡尔积 + 同名列相等条件

= R.B=S.B AND R.C=S.C

σ₃<₆ = 第3列C < 第6列F = R.C < S.F

合起来：

WHERE R.B=S.B AND R.C=S.C AND R.C<S.F

  • 条件之间用 AND（全部满足），不是 OR（满足一个就行）
  • σ₃<₆ 是 C<F，不是 C<B（别看错列号）

```

```sql
SELECT A, R.C, E, F

FROM R, S

WHERE R.B=S.B AND R.C=S.C AND R.C<S.F;
```

官方解析

本题考察的是关系数据库中的自然连接与投影操作。

自然连接（⋈）是基于所有共同属性（此处是 D 和 E）做等值连接，并去除重复的同名属性。

R 有属性：A, B, C, D, E，S 有属性：D, E, F, G

自然连接 R ⋈ S 后的属性集合为：A, B, C, D, E, F, G，共 7 个属性。

π1,2,4,6（R⋈S） 是对自然连接结果的投影操作，选出第1、2、4、6列。

从上面的属性顺序来看：1 → A，2 → B，3 → C，4 → D，5 → E，6 → F，7 → G

所以 π1,2,4,6（R⋈S） 的结果为属性：A, B, D, F，共 4 列。

因此，选项 B 正确。

本题考察的是数据库转储方式的分类与应用场景。

数据库转储是将数据库中全部或部分数据复制到外部存储介质中，以便在发生故障时进行恢复。转储方式主要按操作期间是否允许事务运行和转储范围来分类。

B选项 动态全局转储：全局转储数据库全部数据，动态方式允许在转储期间继续进行事务处理，实现转储与事务并发执行，符合题干描述，正确。

D选项 动态增量转储：增量转储且允许事务并发，但题干要求转储全部数据，而非部分变化数据，因此错误。

分布式数据库两阶段提交协议中的两个阶段是指（）。

子题1

参考答案：C

官方解析

本题考察的是分布式数据库中的二阶段提交协议（Two-Phase Commit, 2PC），它是确保分布式事务一致性的经典算法。

二阶段提交的核心目标：在多个分布式节点参与同一事务时，保证事务的原子性与一致性。

  • 角色：
  • 协调者（Coordinator）：负责组织事务的提交或回滚。
  • 参与者（Participants）：实际执行事务操作的数据库节点。

两个阶段：

  1. 表决阶段（准备阶段，Voting/Prepare Phase）
  • 协调者向所有参与者发送“准备提交事务”的请求。
  • 参与者本地执行事务并记录 redo/undo 日志，但不提交。
  • 各参与者返回“同意提交”或“中止”的表决结果给协调者。
  1. 执行阶段（提交阶段，Commit Phase）
  • 如果协调者收到了所有参与者的“同意提交”，则向所有参与者发送“提交”命令，参与者正式提交并释放锁资源。
  • 如果有任何一个参与者投“中止”，则协调者向所有参与者发送“回滚”命令，参与者执行回滚并释放锁资源。

A加锁/解锁阶段：加锁解锁是事务执行的细节，不是2PC的阶段划分，错误。

B获取阶段/运行阶段：不属于2PC的正式命名，错误。

C表决阶段/执行阶段：准确对应“准备阶段”和“提交阶段”，正确。

D扩展阶段/收缩阶段：这是两阶段锁协议（2PL）的概念，不是2PC，错误。

关系数据库 难度：1

在关系R（A1，A2，A3）和S（A2，A3，A4）上进行关系运算的4个等价的表达式E1、E2、E3和E4如下所示： $E_1 = \pi_{A_1, A_4}(\sigma_{A_2 < 2018 \land A_4 = '95'}(R \bowtie S))$ $E_2 = \pi_{A_1, A_4}(\sigma_{A_2 < 2018}(R) \bowtie \sigma_{A_4 = '95'}(S))$ $E_3 = \pi_{A_1, A_4}(\sigma_{A_2 < 2018 \land R.A_3 = S.A_3 \land A_4 = '95'}(R \times S))$ $E_4 = \pi_{A_1, A_4}(\sigma_{R.A_3 = S.A_3}(\sigma_{A_2 < 2018}(R) \times \sigma_{A_4 = '95'}(S)))$ 如果严格按照表达式运算顺序执行，则查询效率最高的是表达式（）。

子题1

参考答案：B

官方解析

本题考察的是关系代数表达式的等价变换与代价优化原则。

核心原则是：尽可能将选择（σ）下推到越接近数据源越好，尽可能避免先做笛卡儿积（×），优先使用连接（⋈），并减少中间结果规模。题干四式在语义上应等价；常见等价关系为：E1 与 E2 等价（选择下推到连接两端），E3 与 E4 等价（连接转化为对笛卡儿积的选择，并尽量下推选择）。在“严格按写出的运算顺序执行”的前提下，比较中间结果规模与操作类型，E2的执行代价最低。

A选项 E1：先做连接 R ⋈ S，再整体选择 σ{A2<2018 ∧ A4='95'}。先连接后选择会产生较大的中间结果，因为连接在未过滤前参与元组更多，随后再过滤，代价高于先选择再连接，所以不是最优。

B选项 E2：先对 R 与 S 分别执行选择 σ{A2<2018} 与 σ{A4='95'}，再做连接，然后投影。这是标准的“选择下推 + 再连接”策略，能显著缩小参与连接的关系规模，减少连接代价与中间结果，严格按序执行时查询效率最高，因此正确。

C选项 E3：先做笛卡儿积 R × S，再一次性做包含等值连接条件与选择条件的总选择，最后投影。笛卡儿积在未约束时会产生规模巨大的中间结果，随后再用σ过滤，代价通常最高，因此最差。

D选项 E4：先分别下推选择到 R 与 S，随后做笛卡儿积，再用 σ{R.A3=S.A3} 实现等值连接。相比 E3，已经做了部分优化（先选择），中间结果小于 E3；但仍然显式执行了笛卡儿积再过滤为连接，通常劣于直接连接的 E2，因此不是最优。

综上，按照代价最小化与中间结果最小化的优化原则，选择 B（E2）。

此题考察Armstrong 公理系统 的相关概念。

第一问

第二问考察函数依赖和无损分解的相关知识。

🧠 先把专业名词"顾名思义"搞懂

函数依赖 A→B

> 白话：A通过中间人C才能决定B（A不直接决定B）

> 记忆口诀："传话依赖中间人"

>

> 条件：A→C，C→B，但B不能反过来决定A（B↛A）

> 此时 A→B 就叫传递依赖

蕴涵（F蕴涵X→Y）

> 白话：F这堆规则能推导出X→Y这个结论

> 类比：已知"1+1=2"和"2+1=3"，可以推出"1+1+1=3"

> "蕴涵"= 能推出来

Armstrong公理（推理三板斧）

> 记忆："自增传"三字诀

```

┌─────────────────────────────────────────────┐

│ 自 → 自反律：A包含B，则A→B（废话规则） │

│ 增 → 增广律：A→B，则AC→BC（两边加同样的） │

│ 传 → 传递律：A→B，B→C，则A→C（接力推导） │
```

🔍 第二题：无损分解 vs 保持函数依赖

先搞懂两个概念

保持函数依赖

> 白话：把大表拆成小表后，原来的规则一条都不能丢

> 类比：把一本书撕成两半，每半本的内容规则都还在

判断方法：

```

U1={A,B,C} → 保留 A→BC（A,B,C都在U1里）✅

U2={B,D,E} → 保留 B→D，D→E（B,D,E都在U2里）✅

原来F={A→BC，B→D，D→E} 三条全部保留 → 保持函数依赖 ✅

```

无损连接（无损分解）

> 白话：拆开的小表，拼回去还是原来的大表，没有多出垃圾数据

> "无损"= 信息没有损失，也没有凭空多出来

判断公式（记住这个套路）：

```

┌──────────────────────────────────────────────┐

│ 第一步：算交集 U1∩U2 = {B} │

│ 第二步：看交集能不能决定某一边的差集 │

│ U1-U2 = {A,C} │

│ U2-U1 = {D,E} │

│ 第三步：检查 B→{D,E} 是否成立？ │

│ B→D（已知）✅ │

│ B→E（推导出来了）✅ │

│ 交集B 能决定 U2-U1={D,E} → 无损分解 ✅ │

└──────────────────────────────────────────────┘

```

> 记忆口诀："交集能决定差集，就是无损"

参考答案：D

官方解析

此题考察关系数据库的基本理论。

问题 1：考察属性闭包的计算方法。

关系数据库中的 \[X\]+F=Y 闭包求法包括以下三个步骤：（1）将最终结果属性集设为Y，并将Y初始化为空。（2）检查F中的每一个函数依赖 A→B，如果属性集 A 中所有属性均在 Y 中，而B中有的属性不在 Y 中，则将其加入到 Y 中。（3）重复第二步，直到没有属性可以添加到属性集 Y 中为止，得到的 Y 就是 X 的闭包。

A选项（A）+ F根据 A→B 可得（A）+ F = {A，B} ，B选项（B）+ F 因为不存在B为左侧决定因素的函数依赖，所以（B）+ F = {B} ，C 选项（AC）+ F 根据 A→B，BC→E，AC→B 可得（AC）+ F ={A，B，C，E} ，D 选项（AD）+ F 根据 A→B，D→C， BC→E 可得（AD）+ F ={A，B，C，D，E} = U。所以选 D 选项。

问题 2：考察候选码的计算方法。

如果有属性或属性组能唯一标识元组，则它就是候选码。候选码的计算分方法有分析法和作图法。个人建议用作图法。作图法就是根据题目给出的函数依赖画出有向图。然后从起点出发找，看是否能遍历所有节点。一个不行再试另一个起点。最后的结果就是候选码。如下图所示。从图很直观地可以看出，入度为零的结点是 A 与 D，从这两个结点的组合出发，能遍历全图，所以候选码是 AD。

可以看到属性闭包也可以通过先做出有向图，然后从某个点出发遍历得到。比如 A 在 F 上的闭包从图中看出就是 (A，D)。

本题考察的是分布式数据库的四种透明性的基本概念。

分布式数据库系统通常具备四种透明性：分片透明性、复制透明性、位置透明性和局部映像透明性（又称逻辑透明性），它们共同目的是让用户在使用数据时无需关心底层数据的组织与存储方式。

A选项 分片透明：指用户在进行数据操作时，不必关心数据是如何分片的，也无需了解分片位置，系统会自动定位到相应的数据片段并执行操作。它解决的是数据拆分结构的透明性，而不是位置问题，因此不符合题意。

B选项 逻辑透明：又称局部映像透明性，指用户不必关心各站点局部数据库使用的具体数据模型与操纵语言，系统会自动进行数据模型和操作语言的映射与转换。这是数据模型层面的抽象，不涉及物理位置，因此不符合题意。

C选项 位置透明：指用户不需要知道数据的物理存放位置，系统会自动定位到存储数据的站点并完成操作。当数据位置发生变化时（如从一个站点迁移到另一个站点），应用程序无需修改。这正是题干描述的含义，因此正确。

D选项 复制透明：指用户不必关心数据在不同节点的复制情况，系统会自动完成复制数据的更新与维护。它解决的是数据冗余副本的透明性，而非物理位置问题，因此不符合题意。

外模式

> 就是"用户看到的窗口"。比如你在公司系统里只能看到自己的工资，看不到别人的——这个"只给你看的那一块数据的样子"就是外模式。

模式（逻辑模式）

> 就是"数据库的设计图纸"。比如员工表有哪些列（姓名、工号、工资），列和列之间什么关系，这张图纸就是模式。它不管数据怎么存，只管逻辑上长什么样。

内模式（存储模式）

> 就是"数据在硬盘里真实的摆放方式"。比如数据是按某个字段排好序连续存放的（聚簇索引），还是建了一个目录单独存（非聚簇索引），这些都是内模式管的事。

聚簇索引

> "聚簇"= 聚在一起存。数据行按照这个索引的顺序，物理上紧挨着排列在硬盘里。改了聚簇索引，数据在硬盘上的摆放顺序就变了——所以改的是"内模式"（底层存储方式）。

官方解析

本题考察的是关系代数中自然连接与选择、投影的等价变换。

自然连接 R ⋈ S 等价于在笛卡尔积 R × S 上施加同名属性相等的选择，再去掉重复同名属性进行投影，即 $σ_{1=5 ∧ 3=6}(R × S) $之后再做 π 去除重复列。

题干还包含选择条件，对应序号条件为$ σ{2 > 7}$。将三者合并即得到等价表达式$ π{1,2,3,4,7,8}(σ_{1=5 ∧ 2>7 ∧ 3=6}(R × S))$。

A选项：仅有 σ_{2>7}(R × S)，缺少自然连接所需的等值条件（1=5、3=6）以及最终的投影，不等价。

B选项：包含自然连接所需的两个等值条件（1=5、3=6），包含题干的选择条件（2>7），并在最后通过 π_{1,2,3,4,7,8} 去掉重复同名列，完全等价。

C选项：条件写作 2>'7' 将 7 当作字符常量，类型不匹配，且同样缺少自然连接的等值条件与投影，不等价。

D选项：虽含有等值连接条件与投影，但将 7 写成字符常量 '7'（应为数值 7），与题干语义不符，故不等价。

因此，选项 B 正确。

A选项持久性（Durability）：表示一旦事务提交，其所做的修改会永久保存在数据库中，即使系统发生故障也不会丢失，属于事务的基本特性。

C选项一致性（Consistency）：表示事务执行前后，数据库必须从一个一致性状态转换到另一个一致性状态，属于事务的基本特性。

D选项并发性：并发性是数据库系统的一个重要特性，指多个事务可以同时执行，但它不是事务本身的特性。并发控制是数据库管理系统需要实现的机制，以保证在多事务同时进行时仍能保持数据一致性和隔离性。

第33题（题号：11）

数据库基本概念 难度：2

若关系R有m个元组，关系S有n个元组，则R和S的笛卡尔积有（）个元组。

子题1

参考答案：D

官方解析

本题考察的是关系代数中笛卡尔积的基本概念。

笛卡尔积是关系代数中的一种二元操作，用于将两个关系中的每一个元组进行组合，生成一个新的关系。设关系R有m个元组，关系S有n个元组，则R×S表示所有可能的有序对 (r, s)，其中r∈R，s∈S。

A选项 n：只表示了S中的元组数，与笛卡尔积的结果无关，错误。

B选项 m：只表示了R中的元组数，也不正确。

C选项 m+n：表示的是两关系元组数的总和，而不是它们之间的组合数，错误。

D选项 m×n：正确地表示了笛卡尔积中结果元组的数量。每个R中的元组都与S中的n个元组组合，总共生成m×n个元组，正确。

因此，选项 D 正确。

数据库基本概念 难度：2

给定关系模式R \< U ，F \>， U= {A，B，C，D} ， F = {A→C ，AB→D }，则 R 的候选关键字为（）

子题1

参考答案：C

官方解析

本题考察的是关系数据库中候选键的判定，属于高频考点，需要熟练掌握。

候选键是指能唯一标识关系中元组的属性组合，且是最小的（即不包含冗余属性）。

根据题意： 属性集 U = {A, B, C, D}，函数依赖集 F = {A → C, AB → D}

我们通过属性闭包来判断候选键。

1. 计算 A⁺：

A⁺ = {A}，根据 A → C，A⁺ = {A, C}，无法推出 B 或 D，所以 A 不是候选键。

2. 计算 B⁺：

B⁺ = {B}，无法推出其他属性，B 不是候选键。

3. 计算 AB⁺：

AB⁺ = {A, B}，A → C ⇒ AB⁺ = {A, B, C}，AB → D ⇒ AB⁺ = {A, B, C, D}

AB 的闭包是全属性集 U，说明 AB 是超键，且 A⁺ 和 B⁺ 都不能独立推出全属性，说明 AB 是最小超键，即候选键。

4. 计算 C⁺：

C⁺ = {C}，不能推出其他属性，C 不是候选键。

因此，选项 C 正确。

因此，正确答案是：C. 外模式。

三、结合你的 Java/SpringBoot 经验类比

```

外模式 ≈ 你写给前端的 DTO/VO（用户只看到部分字段）
```

数据库基本概念 难度：2

给出关系模式：R(a, b, c, d) 和函数依赖集合 a → cd,c → b，候选键是（）。

子题1

参考答案：A

官方解析

本题考察的是候选键的判断。

方法 1：利用属性闭包法。通过计算属性闭包可以发现，只有 a 的闭包能覆盖所有属性，因此它是关系 R 的候选键。

我们先求 a⁺（a的属性闭包）： a → c,d ，得到 a⁺ 初始为 {a}，由于 a → c,d，加入 c,d 到闭包，可以得到 a⁺ = {a, c, d}，再看 c → b，c ∈ a⁺，所以可推出 b 也可以加入闭包，最终：a⁺ = {a, b, c, d} = R 的所有属性所以，a 是候选键 。

方法 2：用有向图的方式直观地表示函数依赖关系。可以看到从 a 出发能够遍历所有节点，所以 a 是候选码。

一、关键词拆解（不用专业词解释专业词）

函数依赖 a → b

> 顾名思义："a决定b"

> 就像你的身份证号（a）能唯一确定你的姓名（b）

> 知道a，就一定知道b是什么

属性闭包 a⁺

> 顾名思义："a能扩散到哪些属性的集合"

> 就像病毒传播：a能感染谁，被感染的还能继续感染谁，最终所有被感染的人就是闭包

> a⁺ 读作 "a的闭包"，就是从a出发，能推导出的所有属性

候选键

> 顾名思义："候选的钥匙"

> 一张表里，能唯一锁定一行数据的最小属性组合

> "候选"说明可能不止一把钥匙，但每把都够用且不多余

二、本题解题流程

题目条件整理：

```

关系 R 包含属性：a, b, c, d

函数依赖规则：

规则1：a → c, d （知道a，就知道c和d）

规则2：c → b （知道c，就知道b）

```

🔑 方法一：病毒扩散法（属性闭包）

> 问：从 a 出发，能推出哪些属性？

```

第1步：初始只有 a

闭包 = {a}

第2步：看规则1，a → c,d

a 在闭包里 ✅ → 把 c,d 加进来

闭包 = {a, c, d}

第3步：看规则2，c → b

c 在闭包里 ✅ → 把 b 加进来

闭包 = {a, b, c, d}

第4步：闭包 = {a,b,c,d} = R的全部属性 ✅

```

结论：a 一个人就能推出所有属性 → a 是候选键

🔑 方法二：有向图法（更直观）

```

┌─────────────────┐

│ ↓

a ──────→ c ──→ b

│

└──────→ d

```

> 从 a 出发，沿箭头走，能到达 b、c、d 所有节点

> a 是"起点之王" → a 是候选键

验证其他选项为什么不对：

```

b 的闭包：b → ？ 没有任何规则以b开头 → b⁺ = {b} ❌ 不够

c 的闭包：c → b → c⁺ = {c, b} ❌ 不够

d 的闭包：d → ？ 没有任何规则以d开头 → d⁺ = {d} ❌ 不够

```

🧠 记忆口诀

```

候选键判断三步走：

  1. 列出所有函数依赖规则
  2. 对每个属性做"病毒扩散"
  3. 扩散能覆盖全部属性的，就是候选键

```
