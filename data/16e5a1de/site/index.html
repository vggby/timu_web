需求工程 · 结构化知识点清单

知识点名称

需求工程（需求开发 + 需求管理）

核心定义/结论

需求工程分为两大并列模块，不可混淆：

```

需求工程

├── 需求开发（"做出来"）

│ ├── 需求获取 → 问出来

│ ├── 需求分析 → 想清楚

│ ├── 需求建模 → 画出来

│ └── 需求评审 → 检查对不对

│

└── 需求管理（"管起来"）

├── 变更控制 → 改了要走审批

├── 版本控制 → 存好每个版本

├── 需求跟踪 → 跟着需求追到底

└── 需求状态跟踪 → 随时知道进展

```

两个关键概念：

  • 需求基线：需求文档评审通过后的"冻结版本"，是开发工作的正式起点，相当于打了 git tag
  • 需求约定：需求基线形成后，客户与开发方之间对功能/非功能需求的正式共识

典型题型与解题要领

题型1：判断某活动"属于/不属于"需求管理

解题要领：看到"需求获取、需求建模、需求分析、需求评审"任意一个词出现在选项里，直接排除该选项。这四个词全属于需求开发，不属于需求管理。

题型2：填空/单选考需求基线和需求约定

解题要领：

  • "评审批准后定义了开发工作的 ___" → 需求基线
  • "客户和开发者之间构筑的 ___" → 需求约定

题型3：考需求跟踪的定义

解题要领：题干出现"联系文档、依赖关系、追踪、映射、需求与系统元素之间"等词 → 选需求跟踪。需求跟踪的本质是建立需求与架构、代码、测试、文档之间的可追溯关系。

易错点与注意事项

  1. 需求开发 vs 需求管理 最容易混淆
  • 需求评审属于需求开发，不是需求管理
  • 文档管理属于配置管理/项目管理，不属于需求管理
  1. 需求管理是三个还是四个活动
  • 早期教材说三个：变更控制、版本控制、需求跟踪
  • 完整版是四个：加上需求状态跟踪
  • 遇到选项只有三个时，选包含"变更控制、版本控制、需求跟踪"的那个
  1. 需求跟踪 ≠ 需求状态跟踪
  • 需求跟踪：建立需求与其他系统元素的联系（横向追踪）
  • 需求状态跟踪：追踪单条需求当前处于哪个阶段（纵向状态）
  1. 需求基线是桥梁
  • 它连接的是需求开发阶段和需求管理阶段，不是两个开发阶段之间的桥梁

推荐复习顺序

  1. 先建立两大模块的框架区分（需求开发 vs 需求管理），这是所有题目的判断基础
  1. 背住需求管理四个活动的口诀："变版跟状"（变更、版本、跟踪、状态）
  1. 理解需求基线和需求约定的含义，记住它们在流程中的位置
  1. 理解需求跟踪的定义，能识别题干中的关键描述词
  1. 做真题验证，重点练习排除干扰项的能力（尤其是"需求获取/评审"混入需求管理选项的题型）

第1题（题号：18）

需求工程 难度：1

需求管理是一个对系统需求变更、了解和控制的过程。以下活动中，（）不属于需求管理的主要活动。

子题1

参考答案：A

官方解析

本题考察的是需求管理的三大核心活动。

需求管理的核心任务是在整个软件开发生命周期中跟踪、控制和管理需求的变更和状态，确保系统按需构建并满足用户需求。需求管理主要包括以下三个方面：

1. 变更控制：确保对需求变更进行严格的审批、记录与跟踪，防止无序变更，是需求管理的基础机制之一。

2. 版本控制：用于识别不同版本的需求文档，记录需求在时间上的演变，支持对不同版本间的比较和回退。

3. 需求跟踪：确保每一个需求都能从提出到实现、测试都有迹可循，即“需求的前向与后向可追溯性”。

A选项文档管理：尽管文档管理对整个项目来说很重要，但它并不是需求管理的核心组成部分，而是配置管理、项目管理中更广泛的一个内容，正确。

B选项需求跟踪：是需求管理的重要活动之一，错误。

C选项版本控制：用于管理需求文档及其变更，属于需求管理内容，错误。

D选项变更控制：管理需求变更流程的重要机制，属于需求管理内容，错误。

因此，选项 A. 文档管理 正确。

A需求描述把需求写清楚，就像写说明书，把要做什么用文字说明白只是"写清楚"，没有去追踪联系
B需求分析把需求想清楚，分析哪些能做、哪些优先做、哪些有问题只是"想清楚"，没有去追踪联系
C需求获取把需求问出来，去找用户聊天、发问卷、观察用户行为，收集他们想要什么只是"问出来"，还没开始追踪
D需求跟踪把需求和所有相关东西建立联系档案，记录这个需求被哪段代码实现、被哪个测试验证、在哪个文档里有说明✅ 正确答案

🗺️ 需求工程全流程·顺序记忆

```

第一步：需求获取

└─ 【问】去问用户要什么

↓

第二步：需求分析

└─ 【想】分析这些需求合不合理、能不能做

↓

第三步：需求描述

└─ 【写】把确认好的需求写成文档

↓

第四步：需求跟踪

└─ 【追】追踪需求有没有被正确实现

```

口诀：问 → 想 → 写 → 追

🔑 需求跟踪·核心要点

需求跟踪矩阵（考试高频词）

白话理解：就是一张大表格

```

┌──────────┬──────┬──────┬──────┬──────┐

│ 需求编号 │ 架构 │ 代码 │ 测试 │ 文档 │

├──────────┼──────┼──────┼──────┼──────┤

│ 需求001 │ 模块A│ 类B │ 用例C│ 第3章│

│ 需求002 │ 模块D│ 类E │ 用例F│ 第5章│

└──────────┴──────┴──────┴──────┴──────┘

```

这张表就是在追踪每个需求的"下落"

✅ 复习到什么程度可以考试

这道题只需要记住一件事：

> 需求跟踪 = 建立需求与其他所有东西（代码、测试、文档、架构）之间的联系档案

判断标准：

  • 看到题目里出现 "联系文档"、"依赖关系"、"追踪"、"映射" 这类词 → 选需求跟踪
  • 能区分四个选项各自干什么 → 足够应试

不需要深入研究需求跟踪矩阵的具体格式，认识概念即可。
